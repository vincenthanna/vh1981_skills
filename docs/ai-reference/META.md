# META: 프로젝트 생성 지시사항 역추론

> 이 저장소(`anthropic_repos`)가 어떤 지시사항/프롬프트를 통해 만들어졌는지를 기존 콘텐츠 패턴으로부터 역추론하여 기록한 문서

---

## 1. 이 문서의 목적

이 저장소는 `github.com/anthropics`의 공개 저장소 37개를 8개 카테고리로 분류하고, 각 저장소를 마크다운 문서로 정리한 **레퍼런스 문서 모음**이다. 코드가 아닌 문서만으로 구성되어 있으며, git 저장소가 아닌 로컬 디렉토리 형태로 관리된다.

이 META.md는 해당 저장소를 구성하기 위해 사용되었을 **원본 지시사항(프롬프트)을 역추론**하여 기록함으로써:

- 동일한 구조의 문서 저장소를 재현할 수 있게 한다
- 새로운 저장소 추가 또는 기존 문서 수정 시 일관된 규칙을 따를 수 있게 한다
- 프로젝트의 설계 의도와 분류 기준을 명문화한다

## 3. 문서 작성 규칙 (역추론)

### 3.1 공통 규칙

- 모든 개별 저장소 문서는 `---` (YAML frontmatter 구분자)로 시작한다
- 파일명은 GitHub 저장소 이름과 동일하게 `.md` 확장자를 붙인다 (예: `anthropic-sdk-python.md`)
- 원본 저장소의 README 내용을 기반으로 핵심 정보를 추출한다

### 3.2 카테고리별 문서 작성 패턴

#### SDK 문서 (`01_SDK/`)

포함할 내용:
- 라이브러리 이름 및 설명
- 설치 명령어 (`pip install`, `npm install`, `go get` 등)
- 기본 사용 예시 (해당 언어의 코드)
- 요구사항 (언어 버전)
- 라이선스 정보

예시 구조:
```
---
[SDK 이름]
설명
Documentation 링크
Installation 명령어
Getting started 코드 예시
Requirements
Contributing
License
```

#### Product 문서 (`02_Product/`)

포함할 내용:
- 제품 개요 (한국어 번역 포함 가능)
- 설치 방법 (여러 플랫폼별 설치 명령어)
- 주요 기능 설명
- CLI 명령어 (해당하는 경우)
- 플러그인/확장 정보
- 버그 신고 및 커뮤니티 안내
- 데이터 수집/개인정보 정책

#### Tutorial 문서 (`03_Tutorial/`)

포함할 내용:
- 학습 자료 개요
- 포함된 튜토리얼/코스 목록
- 사전 요구사항
- 시작 방법

#### Research 문서 (`04_Research/`)

포함할 내용:
- 데이터셋 또는 논문 코드 설명
- 원본 논문 인용 정보 (제목, 링크)
- 데이터 형식 설명 (필드 목록 등)
- **면책 조항** (Disclaimer): 민감한 콘텐츠가 포함될 수 있음을 경고
- 연락처 정보

예시 구조:
```
---
Overview
[Deprecated 알림이 있으면 포함]
데이터셋 설명
Disclaimer (민감 콘텐츠 경고)
데이터 형식 상세 (필드별 설명)
Contact
```

#### Integration 문서 (`05_Integration/`)

포함할 내용:
- 서비스/도구 개요
- Use Cases
- Prerequisites (Docker, 토큰 등)
- 설치 및 설정 방법 (VS Code, Claude Desktop, CLI 등 환경별)
- **도구(Tools) 목록 테이블**: 함수명, 설명, 파라미터 상세
- 환경변수 설명
- 리소스(Resources) 정보

예시 구조:
```
---
[서비스명]
개요
Use Cases
Prerequisites
Installation (환경별 JSON 설정 예시)
Tool Configuration (toolset 목록 테이블)
Tools (함수별 파라미터 상세)
Resources
License
```

#### Plugin 문서 (`06_Plugin/`)

포함할 내용:
- 플러그인/스킬 시스템 설명
- 설치 방법 (마켓플레이스, CLI 명령어)
- 스킬 목록 및 구조
- 커스텀 스킬 생성 방법 (SKILL.md 형식)
- 파트너 스킬 정보

#### Vertical 문서 (`07_Vertical/`)

포함할 내용:
- 산업별 솔루션 개요
- 마켓플레이스 정보
- 사용 가능한 스킬/플러그인 목록
- 적용 사례

#### Safety 문서 (`08_Safety/`)

포함할 내용:
- 개요 (헌법, 보안, 모니터링 등의 목적)
- 문서 구성 설명
- 핵심 원칙 또는 가이드라인
- 라이선스 (예: CC0 1.0)
- 관련 블로그 포스트/외부 문서 링크

## 4. 디렉토리 구조 규칙

### 4.1 번호 접두사

```
anthropic_repos/
├── README.md                          # 루트: 전체 목차 (한국어)
├── CLAUDE.md                          # Claude Code 컨텍스트
├── META.md                            # 이 문서
├── 01_SDK/                            # 번호 접두사로 논리적 순서 부여
│   ├── README.md                      # 카테고리 README
│   ├── anthropic-sdk-python.md        # 개별 저장소 문서
│   ├── anthropic-sdk-typescript.md
│   └── ...
├── 02_Product/
│   ├── README.md
│   ├── claude-code.md
│   └── ...
├── 03_Tutorial/
├── 04_Research/
├── 05_Integration/
├── 06_Plugin/
├── 07_Vertical/
└── 08_Safety/
```

### 4.2 번호 체계의 의미

번호 접두사(`01_` ~ `08_`)는 **기초에서 전문으로** 향하는 논리적 순서를 나타낸다:

1. **SDK** - API 접근의 기초
2. **Product** - 핵심 제품
3. **Tutorial** - 학습 자료
4. **Research** - 연구 및 평가
5. **Integration** - 외부 시스템 통합
6. **Plugin** - 확장 기능
7. **Vertical** - 산업별 특화
8. **Safety** - 안전 및 거버넌스

### 4.3 파일 명명 규칙

- 카테고리 디렉토리: `{번호}_{영문 카테고리명}/` (예: `01_SDK/`)
- 카테고리 설명: `README.md`
- 개별 문서: `{GitHub 저장소 이름}.md` (예: `anthropic-sdk-python.md`)
- 저장소 이름에 하이픈(`-`)을 그대로 유지

## 5. 번역 규칙

### 5.1 언어별 적용 범위

| 파일 유형 | 언어 | 비고 |
|-----------|------|------|
| 루트 `README.md` | 한국어 | 전체 목차, 카테고리 설명 |
| 루트 `CLAUDE.md` | 한국어 | Claude Code 컨텍스트 |
| 카테고리 `README.md` | 한국어 | 카테고리 제목(이모지 + 영문), 설명은 한국어 |
| 개별 저장소 `.md` | 영어 기반 | 원본 저장소 README 내용 반영 |

### 5.2 번역 상태

- 루트 README, 카테고리 README: **한국어 완료**
- 개별 저장소 문서: **영어 기반** (원본 저장소 내용 그대로 또는 요약)
- 일부 Product 문서(예: `claude-code.md`): **한국어 번역 완료**
- 나머지 개별 문서: 한국어 번역 진행 중

### 5.3 번역 시 유의사항

- 기술 용어(SDK, API, MCP, CLI 등)는 영문 그대로 사용
- 저장소 이름, 패키지 이름, 명령어는 번역하지 않음
- 카테고리 README의 제목 형식: `# {이모지} {영문 카테고리명} — {한국어 설명}`
  - 예: `# 🛠️ SDK — 언어별 공식 클라이언트`

## 6. 업데이트 가이드

### 6.1 새 저장소 추가 절차

1. **카테고리 결정**: 저장소의 성격에 맞는 카테고리(01~08) 선택
2. **개별 문서 작성**: 해당 카테고리 디렉토리에 `{저장소이름}.md` 파일 생성
   - `---`로 시작
   - 원본 저장소 README에서 핵심 내용 추출
   - 카테고리별 문서 패턴(섹션 3.2) 준수
3. **카테고리 README 업데이트**: 저장소 목록에 새 항목 추가
   - 형식: `- [저장소이름](./저장소이름.md) — https://github.com/anthropics/저장소이름`
   - 알파벳 순서 유지
4. **루트 README 업데이트**: 해당 카테고리의 저장소 수 갱신
5. **CLAUDE.md 업데이트**: 필요 시 핵심 저장소 테이블, 라우팅 테이블 갱신

### 6.2 기존 문서 업데이트 절차

1. 원본 GitHub 저장소의 최신 README 확인
2. 변경 사항(새 기능, 설치 방법 변경, 지원 중단 등)을 반영
3. deprecated 저장소의 경우 상단에 `Note` 표시 (예: hh-rlhf.md 패턴 참고)
4. 기존 문서 형식과 일관성 유지

### 6.3 카테고리 변경 절차

1. 기존 카테고리 디렉토리에서 `.md` 파일 이동
2. 출발 카테고리 README에서 해당 항목 제거
3. 도착 카테고리 README에 해당 항목 추가
4. 루트 README의 저장소 수 갱신 (양쪽 카테고리 모두)
5. CLAUDE.md의 관련 테이블 갱신

### 6.4 새 카테고리 추가 절차

1. 다음 번호의 디렉토리 생성 (예: `09_NewCategory/`)
2. 카테고리 `README.md` 작성 (이모지 + 영문명 + 한국어 설명 + 저장소 목록)
3. 개별 저장소 문서 작성
4. 루트 `README.md` 테이블에 새 행 추가
5. `CLAUDE.md`의 구조, 핵심 저장소 테이블, 라우팅 테이블 모두 갱신

## 7. CLAUDE.md의 역할 (역추론)

`CLAUDE.md`는 Claude Code가 이 저장소를 효과적으로 활용하기 위한 컨텍스트 파일로, 다음 정보를 포함한다:

- **구조 설명**: 디렉토리 트리와 각 카테고리의 역할
- **문서 형식 규칙**: YAML frontmatter, 코드 예시 포함 등
- **핵심 저장소 테이블**: 카테고리별 대표 저장소
- **작업별 참조 라우팅**: 사용자 질문의 키워드에 따라 어떤 디렉토리/파일을 먼저 읽을지 안내
- **편집 시 주의사항**: 새 저장소 추가, 번호 접두사, 마크다운 형식 일관성

이 파일을 통해 Claude Code는 사용자의 질문에 적합한 문서를 빠르게 찾아 참조할 수 있다.
