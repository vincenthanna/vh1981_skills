## 보고서 규칙

문서 구조와 문장은 `doc-style.md`, 문체와 시각 자료는 `output-principles.md` 를 따른다(vh1981 플러그인 `guidelines/`). 아래는 이 명령에만 해당하는 규칙이다.

### 내용 원칙

- 최종적으로 발견/추론/판단한 **사실만** 본문에 쓴다.
- 시행착오 과정, 잘못으로 판별된 내용, 원인으로 추정했다가 아닌 것으로 판별된 것은 본문에서 뺀다.
- 다만 다른 사람이나 하위 에이전트가 주장했는데 직접 확인해 보니 재현되지 않은 것은 지우지 않고, 맨 뒤 "검증 기록" 표에 남긴다. 지우면 다음 사람이 또 믿는다.
- 코드 수정 내용과 테스트 환경 구성은 넣지 않는다.

### 요약 (보고서 첫 부분)

- 3~5문장의 완전한 문장으로 쓴다. 누가, 무엇을, 왜 했고 결과가 무엇인지, 원인과 결과가 분명하게 보이도록 쓴다.
- 꾸밈 많은 산문체나 논문체를 쓰지 않는다. 결론을 첫 문장에 둔다.

### 형식

- markdown으로 저장한다. 측정 결과에는 분포 정보(avg, min, max, 백분위)와 단위(ms, fps, % 등)를 붙인다.
- 비교와 측정값은 표로, 흐름과 구조는 mermaid 도식으로 보여 준다. 표만 나열하지 않는다.
- 추세, 분포, 기전처럼 그래프나 애니메이션이 있어야 이해되는 내용이 있거나 읽는 사람이 따로 있으면, markdown을 저장한 뒤 `vh1981:techreport` 로 HTML 보고서를 만들지 제안한다.

## 작업

1. 현재 conversation에서 관련 데이터/분석 결과를 수집한다.
2. 위 규칙에 따라 보고서를 작성한다.
3. 보고서를 markdown 파일로 저장한다.
