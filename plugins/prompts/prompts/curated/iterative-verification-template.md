## 목적
시뮬레이터/테스트로 전체 데이터 검증 → 문제 발견 → 원인 분석 → 수정 → 재검증 반복

## 템플릿
```
{{검증대상}}을 검증해라.

문제가 있으면:
1. 원인 분석 ({{분석방법}} 출력)
2. 문서 + 코드 둘 다 수정
3. 전체 재검증

평가 기준:
- {{기준1}}
- {{기준2}}
- {{기준3}}

결과를 요약 테이블로 출력해라.
```

## 사용 예시
```
모든 vision_data_xxx_fixed.csv 파일들을 시뮬레이터로 검증해라.

문제가 있으면:
1. 원인 분석 (해당 시점의 timestamp들 출력)
2. 문서 + 코드 둘 다 수정
3. 전체 재검증

평가 기준:
- burst 프레임수/전체 프레임 수 < 20%이면 문제없음
- 연속 수정 실패 < 50개 (10초 기준)
- diff 경향성 판단

결과를 요약 테이블로 출력해라.
```

## 변수 설명
- `{{검증대상}}`: 검증할 파일들 또는 시스템
- `{{분석방법}}`: 로그, 타임스탬프, 메트릭 등 분석에 사용할 데이터
- `{{기준N}}`: 구체적인 평가 기준과 임계값

## 핵심 패턴
1. 설계 철학을 먼저 명확히 전달
2. 시뮬레이터로 전체 데이터 검증 → 문제 발견 → 원인 분석 → 수정 → 재검증 반복
3. 평가 기준을 데이터 특성에 맞게 반복 조정
4. 문서와 코드를 항상 동시에 수정하여 일관성 유지
