# Markdown Tidy

> **목적: markdown 의 공백·빈 줄을 정돈하고, 깨진 문법을 고친다 — 보수적 최소 수정으로.**
> 텍스트·코드·URL·수치 등 **의미 있는 내용은 절대 바꾸지 않는다.** 공백과 구문만 손댄다.
> 결과는 작은 diff. 포매터로 전체를 재정렬하지 않는다 (목록 마커·번호·정렬 통일 ✗).

---

## 입력 (`$TARGET`)

- 이 skill 의 인자는 **markdown 파일 경로** 또는 **디렉토리 경로**다 (`$TARGET`).
  - 파일 → 그 파일 하나를 정리한다.
  - 디렉토리 → 하위까지 **재귀**로 `*.md` / `*.markdown` 을 모두 정리한다
    (`.git`, `node_modules`, `dist`, `build`, `vendor` 등은 제외 — 스크립트가 알아서 거른다).
- 인자가 없으면:
  - 이번 세션에서 방금 다룬 md 가 명확하면 그것을 대상으로 삼고, 시작 전 한 줄로 확인한다.
  - 후보가 불분명하면 어떤 파일/디렉토리를 정리할지 사용자에게 묻는다 (추측해서 진행하지 않는다).
- 파일을 **직접(in-place) 수정**하고, 끝나면 파일별 변경 요약을 보고한다 (미리보기·승인 단계 없음).

---

## 두 가지 작업

### Job 1 — 공백/빈 줄 정리 (결정론적 · 스크립트)

`scripts/normalize_whitespace.py` 가 처리한다. **코드펜스 내부는 절대 건드리지 않는다.**
펜스 밖에서만 아래를 적용한다:

1. 줄끝(trailing) 공백·탭 제거.
2. 연속 빈 줄 3개 이상 → 2개로 축소 (빈 줄은 최대 2개까지 허용; 1~2개는 그대로 둔다).
3. 파일 맨 앞 빈 줄 제거.
4. 파일 맨 끝 빈 줄 제거 + 개행 정확히 1개로.
5. ATX 헤딩 마커 뒤 다중 공백 → 1칸 (`#   제목` → `# 제목`). 마커 종류·레벨은 그대로.

> 펜스(``` 또는 ~~~) 내부의 공백·빈 줄·줄끝 공백은 의미가 있을 수 있어 **그대로 보존**한다.
> 멱등(idempotent)하다 — 두 번 돌려도 같은 결과.

### Job 2 — 깨진 문법 수정 (판단 · 에이전트)

스크립트가 못 하는, **판단이 필요한 구문 깨짐**만 사람이 읽고 고친다. 확실한 구조 오류만:

- **닫히지 않은 코드펜스** — 여는 ```` ``` ````/`~~~` 에 짝이 없으면 닫아준다. 펜스 마커 백틱
  개수·언어 라벨 깨짐 보정.
- **깨진 표** — 헤더 구분선(`|---|---|`) 누락, 파이프 개수 불일치로 렌더가 깨질 때 구분선·파이프
  보정. **셀 내용은 바꾸지 않는다.**
- **마커 뒤 공백 누락** — `#제목`→`# 제목`, `-항목`→`- 항목`, `>인용`→`> 인용` 처럼 명백히
  헤딩/목록/인용으로 의도된 줄. 단 `#hashtag` 같이 본문일 가능성이 있으면 **고치지 않고 보고만** 한다.
- **목록 마커 뒤 다중 공백** — `-  b` → `- b` (마커 종류는 유지). 중첩 목록 정렬을 깨뜨릴 우려가
  있으면 건드리지 않는다.
- **깨진 링크/이미지** — `[text](url` 처럼 괄호가 안 닫힌 명백한 구문 오류만 닫는다.
  **URL·링크 텍스트를 추측해서 새로 만들지 않는다.**
- **짝 안 맞는 강조** — `**bold` 처럼 닫힘이 없는 게 명백할 때만 신중히.

---

## 절대 규칙 (안전)

- **코드펜스/인라인 코드/HTML 블록/수식/frontmatter 내부는 변형하지 않는다** (verbatim 보존).
- **의미 있는 내용은 바꾸지 않는다** — 본문 텍스트·코드·URL·수치·날짜는 그대로. 공백·구문만.
- **포매터식 전체 재정렬 금지** — 목록 마커 통일(`*`→`-`), 순서목록 재번호, 표 컬럼 정렬, 줄바꿈
  reflow 등은 하지 않는다. diff 는 작게.
- **추측해서 만들지 않는다** — 깨진 부분의 원래 의도가 불확실하면 고치지 말고 **보고**한다.

## 작업 절차

1. **대상 확정** — `$TARGET`(파일/디렉토리). 디렉토리면 재귀.
2. **Job 1 실행** — `scripts/normalize_whitespace.py` (이 skill 디렉토리 안) 로 공백/빈 줄을
   정리한다. 먼저 `--dry-run` 으로 규모를 본 뒤 적용해도 된다:
   ```bash
   python3 <이 skill 디렉토리>/scripts/normalize_whitespace.py "$TARGET"   # python3 필요
   ```
   (`<이 skill 디렉토리>` 는 이 SKILL.md 가 있는 폴더의 절대경로다. 플러그인 설치 환경이면
   `${CLAUDE_PLUGIN_ROOT}/skills/md-tidy/scripts/normalize_whitespace.py` 로도 동일하게 실행된다.)
3. **Job 2 실행** — Job 1 로 정돈된 각 파일을 Read 하고, 위 "깨진 문법"만 Edit 로 **보수적으로**
   고친다. 파일이 많으면 한 파일씩. 문법 이상이 없으면 그 파일은 손대지 않는다.
4. **보고** — 아래 형식으로 파일별 요약. 고치지 못하고 남긴(불확실한) 항목은 따로 표시한다.

## 보고 형식

```
정리 완료 — N개 파일 (변경 M / 그대로 N-M)

docs/a.md
  · 공백: 줄끝공백 12, 빈줄축소 4, EOF개행 1
  · 문법: 닫히지 않은 코드펜스 1곳 보강 · 표 구분선 1곳 보정
docs/sub/b.md
  · 변경 없음 (이미 정상)

⚠ 판단 보류 (사용자 확인 필요)
  - docs/a.md:42  깨진 링크 `[참고](` — 원래 URL 을 알 수 없어 그대로 둠
```

## 점검 (수정 후)

- [ ] 코드펜스/인라인코드/HTML/frontmatter **내부 무변형** (공백·빈 줄 포함)
- [ ] 본문 텍스트·코드·URL·수치 등 **의미 내용 무변경** — 공백·구문만 손댔다
- [ ] 줄끝 공백 제거 · 연속 빈 줄 최대 2개로 (3개 이상만 축소) · 파일 끝 개행 1개
- [ ] 닫히지 않은 펜스/깨진 표·링크 등 **구조 깨짐만** 보정 (포매터식 전체 재정렬 ✗)
- [ ] 불확실한 깨짐은 고치지 않고 **보고**에 명시
- [ ] (가능하면) 스크립트를 한 번 더 돌려 **멱등성** 확인 — 추가 변경이 없어야 한다

## 실행

```
입력: $TARGET (md 파일 또는 디렉토리)
1. 대상 확정 (디렉토리는 재귀)
2. Job 1: normalize_whitespace.py 로 공백/빈 줄 정리 (코드펜스 내부 보존)
3. Job 2: 각 파일 Read → 깨진 문법만 보수적으로 Edit
4. 파일별 변경 요약 + 판단 보류 항목 보고
```

> 목적은 "보기 좋고 안 깨진 markdown". 내용은 그대로 두고, 공백과 구문만 최소로 손본다.
