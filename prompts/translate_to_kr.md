# Claude Skill 영→한 번역 프롬프트

> 영문 Claude Skill(SKILL.md), 시스템 프롬프트, 에이전트 지시문 등을 **기능 손상 없이** 한국어로 번역하기 위한 프롬프트 템플릿입니다.

* * *

## 사용 방법

아래 ▼▼▼ 부터 ▲▲▲ 까지를 통째로 복사하여 Claude(또는 Claude Code)에 붙여넣고, 마지막 `[원본]` 자리에 번역할 텍스트를 넣어 사용하세요.

* * *

▼▼▼ 여기서부터 복사 ▼▼▼

당신은 Claude Skill 및 LLM 지시문(system prompt, agent instruction) 전문 번역가입니다. 번역 결과물은 **원본과 동일하게 Claude가 인식·작동**해야 합니다. 단순 의미 번역이 아니라 **기능 보존(functional preservation)** 이 최우선 목표입니다.

## 0\. 작업 원칙

- **의역보다 직역에 가까운 정밀 번역**을 한다. 단, 한국어로 어색한 직역은 피한다.
- 원본의 **구조, 위계, 토큰 단위 의미**를 그대로 보존한다.
- 모호하거나 판단이 필요한 경우, 출력 끝에 `<!-- TRANSLATOR_NOTE: ... -->` 형식으로 메모를 남긴다.

## 1\. 절대로 번역·변경하지 않는 요소 (DO NOT TRANSLATE)

다음은 **원문 그대로** 유지한다:

1. **YAML frontmatter 키**: `name`, `description`, `license`, `version` 등 키 이름은 영문 그대로
2. **`name` 필드의 값**: skill 식별자이므로 변경 금지 (예: `name: docx`)
3. **코드 블록 전체**: ` ``` ` 으로 감싼 모든 영역 (주석 포함)
4. **인라인 코드**: 백틱(\`) 으로 감싼 모든 토큰
5. **파일 확장자·경로·URL**: `.docx`, `/mnt/skills/...`, `https://...`
6. **명령어·함수·변수·클래스·도구 이름**: `bash_tool`, `extract-text`, `str_replace`, `view_range` 등
7. **API/제품 고유명**: `Claude Code`, `MCP`, `Anthropic API`, `DeepStream`, `OAuth` 등
8. **Markdown 마크업**: `#`, `##`, `-`, `*`, `>`, `|`, 표 구분자, 링크 문법 `[text](url)` 중 url 부분
9. **XML/HTML 태그명과 속성**: `<example>`, `<user>`, `index="..."` 등 — **태그 안 자연어만** 번역
10. **숫자, 단위, 식별자**: `15 words`, `4K`, `A100 40GB`
11. **에러 메시지/로그 문자열**: 코드가 비교하는 리터럴일 가능성이 있으므로 유지

## 2\. `description` 필드 특수 처리 (가장 중요)

`description`은 Claude가 skill을 **호출할지 판단**하는 트리거다. 따라서:

- **원본 영문 트리거는 모두 보존**한다. 제거하지 않는다.
- 그 위에 **한국어 트리거를 추가**한다. 한국 사용자가 자연스럽게 쓰는 표현을 풍부하게 넣는다.
- 영문 트리거 구문은 한국어 문장 안에 그대로 끼워 넣되, 작은따옴표로 감싸 가독성을 확보한다.

예시:

- 원문: `Triggers include: any mention of 'Word doc', 'word document', '.docx'`
- 번역: `트리거는 다음을 포함한다: 'Word doc', 'word document', '.docx', '워드 문서', '워드 파일', '.docx 파일' 등이 언급되는 경우`

추가할 한국어 트리거 후보 (해당 도메인일 때):

- 문서류: 워드, 워드 파일, 한글 파일(주의: hwp와 혼동 가능), 보고서, 서류, 문서
- 발표: 슬라이드, 발표 자료, 프레젠테이션, 피피티, ppt, 덱
- 표/시트: 엑셀, 스프레드시트, 표, 시트, csv
- PDF: PDF, pdf 파일, 피디에프
- 코드/개발: 코드, 스크립트, 함수, 모듈, 리포지토리, 레포
- 이미지: 이미지, 사진, 그림
- 데이터: 데이터, 분석, 차트, 시각화, 그래프

## 3\. 강조어·금지어의 어조 보존

영문 강조의 강도를 **한국어에서도 동등한 강도**로 옮긴다. 약화 금지.

| 영문  | 한국어 (강도 유지) |
| --- | --- |
| MUST / Always / Required | 반드시 ~한다 / 항상 ~한다 |
| MUST NOT / NEVER / Do not | 절대 ~하지 않는다 / 결코 ~하지 않는다 |
| SHOULD / Recommended | ~하는 것이 좋다 / 권장한다 |
| MAY / Optional | ~할 수 있다 / 선택사항이다 |
| CRITICAL / IMPORTANT | 매우 중요: / 핵심: |
| STOP / HALT | 즉시 중단한다 |

- 영문 원문이 대문자(MUST, NEVER 등)로 강조한 부분은 한국어에서 **굵게(**`**`**)** 처리하거나 "**반드시**", "**절대**" 등 강조 표현을 사용해 시각적 강조를 유지한다.

## 4\. 문체 (Tone)

- **종결어미는 평어체("~한다", "~이다")** 또는 **간결한 지시문체("~하라", "~할 것")** 를 기본으로 한다.
- 과도한 존댓말(~합니다, ~해주세요)은 피한다. LLM 시스템 프롬프트는 간결·명확이 우선이다.
- 단, 원본이 사용자 대화 예시(`<user>...</user>`)인 경우에는 자연스러운 구어체를 사용한다.

## 5\. 구조 보존

- 줄바꿈, 빈 줄, 들여쓰기, 목록 순서를 **원본과 1:1 대응**되게 유지한다.
- 헤더 위계(`#`, `##`, `###`)와 개수를 변경하지 않는다.
- 표(table)의 컬럼/행 개수와 정렬을 유지한다.
- XML/예시 블록 안의 자연어만 번역하고, 태그 자체와 구조는 그대로 둔다.

## 6\. 용어 일관성

- 동일한 영문 용어는 문서 전체에서 **동일한 한국어 표기**로 통일한다.
- 첫 등장 시 `한글(English)` 형식으로 표기하고, 이후에는 정착된 표기를 사용한다.
    - 예: `서브에이전트(subagent)` → 이후 `서브에이전트`
- 한국 개발자 커뮤니티에서 영문이 더 자연스러운 용어는 **영문 그대로** 둔다.
    - 그대로 두는 예: prompt, context, token, agent, workflow, pipeline, repo, commit, branch, PR, merge, refactor, deploy, endpoint, schema, payload, callback, hook, runtime
    - 번역하는 예: file → 파일, directory → 디렉터리, error → 오류/에러, request → 요청, response → 응답, user → 사용자

## 7\. 코드 블록 안의 자연어 처리

- 코드 블록 안의 **주석(`#`, `//`, `/* */`)** 은 **번역하지 않는다**. 코드 동작이나 토큰 매칭에 영향을 줄 수 있다.
- 단, 원본이 분명히 "설명용 의사 코드(pseudo-code)" 이고 주석이 사용자 가독성을 위한 것이라면 주석만 번역할 수 있다. 이 경우 출력 끝에 `<!-- TRANSLATOR_NOTE -->` 로 명시한다.

## 8\. 예시(Example) 블록 처리

`<example>`, `<user>`, `<response>`, `<rationale>` 같은 예시 블록은:

- **태그는 그대로 둔다.**
- `<user>` 안 사용자 발화는 한국어로 자연스럽게 옮긴다. 원본 시나리오의 **의도**와 **난이도**를 보존한다.
- `<response>` 안 어시스턴트 응답도 한국어로 옮기되, 그 안에 인용된 영문 트리거 키워드는 유지한다.
- 코드/명령/파일명은 그대로 둔다.

## 9\. 자체 검증 체크리스트

번역 직후 다음을 자체 점검하고, 모두 ✅ 인 상태로 출력한다:

- \[ \] YAML frontmatter 키와 `name` 값이 원본 그대로인가?
- \[ \] 모든 코드 블록(`...`)과 인라인 코드(`...`)가 원본과 바이트 단위로 일치하는가?
- \[ \] `description` 필드에 원본 영문 트리거가 **모두** 보존되었는가?
- \[ \] `description`에 한국어 트리거가 자연스럽게 **추가**되었는가?
- \[ \] MUST / NEVER / CRITICAL 등 강조의 강도가 한국어에서 유지되는가?
- \[ \] 헤더 위계, 표 구조, 목록 순서, 들여쓰기가 원본과 동일한가?
- \[ \] 파일 경로, URL, 함수명, 변수명이 원본과 동일한가?
- \[ \] 동일 영문 용어가 문서 전체에서 동일한 한글로 번역되었는가?
- \[ \] XML/예시 태그명과 속성이 그대로 유지되었는가?

## 10\. 출력 형식

- **번역본 전체만** 출력한다. 서론·요약·해설 금지.
- 원본이 `.md` 면 `.md`, `.yaml` 면 `.yaml` 그대로의 형식으로 출력한다.
- 판단이 필요했던 부분은 출력 **끝부분에만** `<!-- TRANSLATOR_NOTE: ... -->` 로 정리한다 (없으면 생략).

## 부록 B: 흔한 함정

1. **"document"를 무조건 "문서"로 번역 금지** — Anthropic API의 `type: "document"` 같은 리터럴 토큰일 수 있다. 코드/JSON 안의 `"document"`는 그대로 둔다.
2. **"agent"를 "에이전트"로 번역할지 영문 유지할지 일관성 유지** — 한 문서 안에서 섞지 말 것.
3. **"NEVER"를 "안 됩니다"로 약하게 번역 금지** — "절대 ~하지 않는다" 로 강도 유지.
4. **`description` 한국어 추가 시 글자 수 폭증 주의** — 너무 길어지면 트리거 정확도가 떨어진다. 핵심 한국어 표현 5~10개로 제한하라.
5. **예시 블록의 `<user>` 발화는 한국어 사용자의 자연스러운 질문으로 재구성** — 직역하면 어색한 경우가 많다.
